# PR 작성

이 PR은 깃허브에서 **사람이 읽는 문서**다. 기술 블로그도 발표 자료도 아니다.
동료 개발자가 리뷰어에게 구두로 설명하듯 쓴다.

읽는 사람이 "AI가 썼네"라고 느끼면 실패다.

## 제목

```
<접두어>: <이 PR이 한 일>
```

`feat:` 또는 `fix:` 가 기본. 코드 동작이 안 바뀌는 PR만 `chore:` / `docs:` / `refactor:` / `test:`.

판단 기준: 이 저장소를 모르는 동료가 제목만 보고 무슨 일인지 아는가.

| | |
|---|---|
| ✅ | `feat: 음식 데이터 사람 승인 전 LLM 최종 검수 배치 추가` |
| ✅ | `fix: 번역 채점 누락 시 멀쩡한 번역까지 폐기되던 문제` |
| ❌ | `채점 모델 전환 및 키 주입 지원` (접두어 없음) |
| ❌ | `feat: KB-286 구현` (뭘 했는지 없음) |

## 본문 구조

````markdown
- [KB-286](https://simhani1.atlassian.net/browse/KB-286)

## 배경

<기존 방식이 어떤 문제였는지. 이 PR이 없으면 뭐가 곤란한지.>

## 변경 내용

### <변경 하나>

<무엇을 바꿨는지. 그리고 왜 그렇게 했는지.>

### <변경 둘>

<무엇을 바꿨는지. 그리고 왜 그렇게 했는지.>

## 고려했던 점

<구현하면서 고민한 것. 다른 방법을 왜 안 골랐는지.>

## 테스트

<어떻게 검증했는지. 검증 안 된 부분이 있으면 그것도.>
````

- 지라 키는 브랜치명에서 뽑는다 (`kb-286-food-review` → `KB-286`). 못 찾으면 지어내지 말고 묻는다.
- `변경 내용`은 3~6개. 커밋 단위가 아니라 리뷰어가 이해하는 단위로 묶는다.
- 각 항목에 **왜 필요한 변경인지**, **다른 선택지를 왜 안 썼는지**(있다면), **리뷰어가 봐야 할 지점**을 녹인다. 항목 제목으로 따로 달지 말고 문장 안에 자연스럽게.
- 흐름도가 설명을 줄여주면 `변경 내용` 안에 mermaid로 넣는다. 없어도 되면 넣지 않는다.

## 문체

문장은 짧게. 한 문단 2~4문장. 수식어를 뺀다.

**이렇게 쓴다**

```
기존에는 사람이 전량 확인해야 했다.
설명과 번역은 내용 검증이 없었다.
그래서 사람 앞에 오기 전에 LLM 검수를 추가했다.

번역은 언어별로 나눠 호출했다.
한 번에 처리하면 출력 JSON이 커져 응답 품질이 떨어졌기 때문이다.
```

**이렇게 쓰지 않는다**

```
본 PR에서는 효율적인 검수 시스템을 구축하였습니다.
안정성을 고려하여 설계하였습니다.
높은 정확도를 보장합니다.
확장 가능한 구조를 적용하였습니다.
```

## 금지 표현

이 단어들은 쓰지 않는다.

| 분류 | 금지어 |
|---|---|
| 섹션명 | 한 줄 요약, 핵심 변경사항, 주요 변경사항 |
| 접속 | 이를 통해, 결과적으로, 궁극적으로 |
| 서술 | 보장한다, 개선하였다, 고도화하였다 |
| 부사 | 효율적으로, 안정적으로, 확장 가능하도록, 견고하게 |
| 성과 | 생산성을 높였다, 사용자 경험을 향상시켰다 |
| 조건부 | 최적화하였다 — 수치나 근거가 있을 때만 |

`안정성` `확장성` `유연성` `견고함` 같은 추상어는 이유를 못 대면 쓰지 않는다.
`~하게 된다` `~할 수 있다` 도 남발하지 않는다.

## 설명 수준

리뷰어가 **코드를 읽기 전에 이해할 정도**까지만.

| | |
|---|---|
| 너무 얕음 | "LLM 검수를 추가했다." |
| 알맞음 | "번역은 9개 언어를 한 호출에 묶었다. 언어별로 나누면 호출이 9배가 되는데, 채점은 원문 하나를 놓고 비교하는 일이라 한 번에 봐도 판단이 흐려지지 않았다." |
| 너무 깊음 | 함수 시그니처와 파라미터 나열 |

코드 한 줄씩 설명하지 않는다. 설계 의도를 설명한다.

## 흔한 실수

| 실수 | 고침 |
|---|---|
| 제목에 접두어 없음 | `feat:` 또는 `fix:` 부터 |
| 배경에 변경 목록을 씀 | 배경은 *문제*를 쓰는 자리 |
| 커밋별로 나열 | 리뷰어가 이해하는 단위로 묶기 |
| "왜"가 빠짐 | 각 항목마다 왜 그렇게 했는지 한 문장 |
| 금지 표현이 섞임 | 위 표를 훑고 고치기 |
| 한 문단이 5문장 넘음 | 끊기 |
