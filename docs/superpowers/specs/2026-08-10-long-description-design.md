# 벡터 검색용 긴 설명 노드 설계 (2026-08-10)

기존 한 문장 설명(255자)은 디스플레이 용도다. 벡터 DB 검색 정확도를 위해
메타데이터 용도의 상세 설명(여러 문장, 500자 이하)을 추가한다.

## 결정: 별도 노드 (4번째 병렬 분기)

- 형식 지시가 상충한다 — 한 문장·마침표 금지 vs 여러 문장 문서. 한 콜에 섞으면 둘 다 흔들린다.
- 프롬프트 튜닝 국면이라 독립 반복이 필요하다 — 분리하면 서로 영향 없음.
- 재시도 비결합 — 디스플레이 설명 탈락이 긴 설명 재생성을 유발하지 않는다.
- 비용은 건당 LLM 콜 +1, 병렬이라 처리 시간 증가 없음.

## 구성

- `LONG_DESC_TEMPLATE` (prompts.py, 레지스트리 `food-long-description`) — 사실 위주:
  정의·분류, 주재료, 조리 방식, 맛 특징, 먹는 방식, 이칭. 홍보 문구 금지.
- `LongDescGen` — 빈 값·500자 초과는 reject (structured output 재시도 1회).
  여러 문장이므로 DescGen 과 달리 마침표를 제거하지 않는다.
- 그래프: `generate_long_description` 노드, clean 팬아웃 4분기 → judge(defer) 합류.
  **검수 없음, judge 판정에도 불참** — 안전 직결 아님, 검색 품질 문제가 실측되면 그때 추가.
- 모델: gen_model (설명 생성과 동일 티어).
- 번역 없음, 한국어만 — 임베딩 대상이 한국어 문서라는 전제.
- `build_ingest_payload` 에 `longDescription` 포함 — **계약 미확정 필드**. POST 가 꺼져
  있는 동안 로그로 형태를 실험하고, 굳으면 적재 계약 갱신 후 POST 복원.
